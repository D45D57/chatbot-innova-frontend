# 🤖 Chatbot para Atención al Cliente

## Documentación del Equipo de Quality Assurance (QA)

## Descripción

Este repositorio contiene la documentación generada por el equipo de
**Quality Assurance (QA)** durante el desarrollo del MVP de un chatbot
para atención al cliente.

El trabajo del equipo QA estuvo orientado a verificar que las
funcionalidades implementadas cumplieran con las User Stories, criterios
de aceptación y requerimientos definidos para el proyecto, manteniendo
la trazabilidad entre requisitos, casos de prueba, ejecución y defectos
encontrados.

------------------------------------------------------------------------

# Objetivos del QA

-   Validar las funcionalidades del chatbot y panel administrativo.
-   Detectar defectos funcionales y de interfaz.
-   Garantizar la calidad del MVP antes de la entrega.
-   Documentar evidencias y resultados de las pruebas.

------------------------------------------------------------------------

# Metodología de trabajo

El proyecto se desarrolló bajo una metodología ágil organizada por
sprints.

El flujo seguido por QA fue:

``` text
Requerimientos
    ↓
Épicas / Features
    ↓
User Stories
    ↓
Casos de prueba
    ↓
Backlog QA (GitHub)
    ↓
Ejecución
    ↓
Reporte de Bugs
    ↓
Retesting
```

# Gestión del Backlog QA

Durante el proyecto se gestionaron tickets específicos para la ejecución
de pruebas por cada User Story, incluyendo:

-   Registro de administrador.
-   Inicio y cierre de sesión.
-   Configuración del negocio.
-   Gestión de FAQ.
-   Inicio de conversación.
-   Navegación conversacional.
-   Consulta de catálogo.
-   Generación de presupuesto.
-   Derivación a atención humana.
-   Registro de clientes.
-   Panel administrativo y métricas.

Cada ticket incluyó:

-   Descripción.
-   Alcance.
-   Casos de prueba asociados.
-   Criterios de aceptación.
-   Definition of Done.
-   Dependencias.
-   Prioridad.

------------------------------------------------------------------------

# Gestión de defectos

Las incidencias detectadas fueron registradas mediante reportes de bugs
con:

-   Identificador.
-   Descripción.
-   Pasos para reproducir.
-   Resultado esperado.
-   Resultado obtenido.
-   Evidencias.
-   Severidad.
-   Prioridad.
-   Estado.

Se identificaron defectos relacionados con:

-   Validaciones de formularios.
-   Cálculo de presupuestos.
-   Persistencia de información.
-   Navegación.
-   Interfaz de usuario.
-   Mensajes de error.
